sage-repro · code walkthrough

What each part of the SAGE code does

A file-by-file and function-by-function guide to the SAGE reproduction kit: what each piece takes in, what it gives back, which part of the paper it implements, and where to change it.

The kit re-implements SAGE: Self-retrieval-augmented generative LLM for emotional support conversation (Yang et al., ESWA 2026). The authors released no code, so every script here was written from the paper's description. Where the paper is silent, the code says ASSUMPTION in a comment. Those are usually the first places you would want to change.

How to read this page. Read "How the files connect" and "The data row" first. They explain the two things every script shares: the list of 8 strategies and the shape of one training example. After that, each file section can be read on its own. The biggest one is sage.py, which is the paper's method.

How the files connect

There are seven Python scripts and two notebooks. Data flows in one direction: raw ESConv becomes JSONL examples, the models read those examples and write predictions, the metrics score the predictions, and compare.py puts the scores beside the paper's.

Two things are imported across files. Changing them changes everything downstream.

  • STRATEGIES in prepare_data.py: the 8 support strategy names. metrics.py, llm_baseline.py and sage.py all import it.
  • generation_metrics, strategy_metrics, retrieval_metrics in metrics.py: every model script scores itself with these.

The data row

Every model in the kit reads the same JSONL files. Each line is one supporter turn that the model must predict. Here is a real row from data/paper/test.jsonl, shortened:

{
  "id": "test-0-5",              // split - dialogue index - turn index
  "dialog_idx": 0,               // which dialogue it came from
  "turn_idx": 5,                 // position of this reply in the dialogue
  "num_prev_turns": 5,           // utterances before it (used for Table 8 buckets)
  "situation": "It is not well to do better information for gather with my friends...",
  "emotion_type": "disgust",
  "problem_type": "problems with friends",
  "context": [                   // everything said before this reply
    {"speaker": "sys", "text": "Hi, can i help today? ...", "strategy": "Question"},
    {"speaker": "usr", "text": "hi", "strategy": null},
    ...
    {"speaker": "usr", "text": "i am in disputed mod with my friends", "strategy": null}
  ],
  "query": "i am in disputed mod with my friends",   // last seeker utterance (u_t in the paper)
  "response": "I am sorry to hear that. So, you and your friends are not seeing eye to eye? ...",  // gold reply
  "strategy": "Question"                              // gold strategy
}

usr is the help-seeker and sys is the supporter. The model sees context (and sometimes situation) and must produce strategy and response. The metrics compare its output against these two gold fields.

prepare_data.py

Paper: Section 4.1 (dataset and split)

Reads the raw ESConv.json and writes six files: train/valid/test for two different splits. You run it once. The outputs are already committed in data/paper and data/zcj.

STRATEGIES

What
The list of 8 ESConv support strategies, in a fixed order.
Used by
metrics (per-strategy F1, entropy), llm_baseline (answer parsing), sage (strategy scoring loops over this list).
Change it
To use a dataset with different labels, edit this list. Then update STRATEGY_DESC in llm_baseline.py to match.

norm(text) → str

What
Collapses repeated spaces and newlines into one space.

reformat(d) → dict

What
Converts one raw ESConv dialogue into a simpler shape: speakers become usr/sys, and only supporter turns keep a strategy.
Takes
One dialogue from ESConv.json.
Gives
{emotion_type, problem_type, situation, dialog: [{text, speaker, strategy?}]}
Why
It copies the logic of the official thu-coai preprocessing, so the zcj split matches the one older baselines used.

split_dialogs(data, mode) → {"train", "valid", "test"}

What
Shuffles the 1,300 dialogues with seed 13 and cuts them into three parts. Splitting by dialogue, not by turn, keeps every test conversation unseen during training.
Modes
paper: 910/130/260 (7:1:2), as SAGE states. zcj: 70/15/15, the split most earlier ESC papers used.
Change it
Change the seed or the ratios here. Every model script picks a split with --split paper or --split zcj, so a new mode name needs a new folder under data/.

to_examples(dialogs, split) → list[dict]

What
Walks each dialogue and emits one row (the shape shown above) for every supporter turn that has at least one seeker utterance before it. Opening greetings with nothing to respond to are skipped.
Change it
This is where you would add a field your own model needs, such as the strategy history or the emotion intensity. Downstream code ignores fields it does not use, so adding is safe.

main()

What
Runs the above for both modes and writes data/{paper,zcj}/{train,valid,test}.jsonl, printing counts.
Run
python prepare_data.py --esconv data/ESConv.json --out data

metrics.py

Paper: Section 4.2, Eqs. 7–10, Tables 1–4

All the evaluation numbers in one place. Nothing here trains or loads a model. It compares text and labels. You can also run it on any predictions file: python metrics.py results/qwen/predictions.jsonl.

MetricMeasuresBetter
ACCShare of turns where the predicted strategy equals the gold strategy.higher
Macro-F1F1 per strategy, then averaged, so rare strategies count as much as common ones.higher
B-2, B-4 (BLEU)Word-pair and 4-word overlap between the reply and the gold reply.higher
D-1, D-2 (Distinct)Share of unique words and word pairs across all replies. Low means repetitive.higher
R-L (ROUGE-L)Longest shared word sequence with the gold reply, β = 1.2 as in Eq. 10.higher
EntropyHow evenly the model spreads its strategy choices (max log₂8 = 3).higher
Bias (JSD)Distance between the model's strategy distribution and a uniform one.lower
R@K, MRR@10, nDCG@10Whether, and how high, the correct reply appears in a ranked list.higher
PPLPerplexity of the gold reply under the model. Computed in the model scripts, not here.lower

tokenize(text) → list[str]

What
Lowercases and splits off . , ? ! so they count as separate words.
Change it
BLEU and Distinct depend heavily on tokenisation. If you compare against a paper that used a different tokenizer (for example nltk's word_tokenize), swap it here and every metric follows.

distinct(hyps, n) · lcs(a, b) · rouge_l(hyp, ref, beta=1.2)

What
Small building blocks. distinct counts unique n-grams over all replies. lcs is the classic longest-common-subsequence dynamic program. rouge_l turns the LCS length into an F-score.

generation_metrics(refs, hyps) → {B-2, B-4, D-1, D-2, R-L}

Takes
Two equal-length lists of strings: gold replies and model replies.
Gives
A dict of scores ×100. BLEU is corpus-level with nltk smoothing method 1 (an assumption; the paper does not say).

strategy_metrics(gold, pred) → {ACC, Macro-F1, Entropy, Bias(JSD), per_strategy_F1}

Takes
Two lists of strategy names.
Gives
Accuracy, Macro-F1 (scikit-learn), and the two bias measures from Table 3, both in log base 2.

retrieval_metrics(ranked_lists, golds, ks=(1, 5, 10)) → {R@1, R@5, R@10, MRR@10, nDCG@10}

Takes
For each query, a ranked list of candidate IDs, and the ID of the one correct candidate.
Note
With exactly one relevant item, nDCG reduces to 1 / log₂(rank + 1).

evaluate_file(path) → dict

What
Reads a predictions file and runs whichever metric groups its rows support: generation if rows have prediction, strategy if they have pred_strategy, retrieval if they have ranked_ids.
Change it
To add a metric (say, BERTScore), write a function, call it here, and add its key to COLS in compare.py.

bm25_baseline.py

Paper: no row of its own; a floor for Tables 1, 4 and 8

BM25 is classic keyword search. It needs no GPU and no training, so it shows what "no learning at all" scores. If a trained model does not beat it, something is wrong. Its result is already in results/bm25_paper/.

query_text(ex, turns=3) → str

What
Joins the last 3 context utterances into the search query.

bucket(n_prev) → "1-2" | "3-4" | "5-6" | ">=7"

What
Groups examples by dialogue length for the Table 8 breakdown. One "turn" is a seeker + supporter pair, so it halves the utterance count.

main()

Part 1
Retrieval. Indexes every gold reply in the test set, searches it with each query, and checks where the query's own gold reply lands. Scored with retrieval_metrics.
Part 2
Generation. Finds the most similar training context and returns that turn's reply and strategy as the "prediction". Scored with generation_metrics and strategy_metrics.
Writes
results/bm25_*/predictions.jsonl and metrics.json.

llm_baseline.py

Paper: Section 4.4, the Qwen / LLaMA / Mistral rows of Tables 1–3

Gives a 7–8B instruction-tuned chat model the conversation plus descriptions of the 8 strategies, and asks it to answer as Strategy: ... then Response: .... No fine-tuning happens. This is the "just prompt an LLM" comparison SAGE claims to beat.

STRATEGY_DESC · SYSTEM

What
One-sentence definitions of each strategy (from the ESConv paper) and the system prompt built from them. The paper never printed its prompt, so this is our version.
Change it
Edit SYSTEM to try few-shot examples, a different persona, or a chain-of-thought step. esc_eval.py imports the same prompt, so the change carries over.

user_prompt(ex, max_turns=10) · build_prompt(tok, ex)

What
user_prompt writes the situation and the last 10 utterances as "Help-seeker:" / "Supporter:" lines. build_prompt wraps system + user messages in the model's own chat template. Mistral's template rejects a system role, so the fallback merges the system text into the user message.

parse(text) → (strategy, response)

What
Reads the model's output with regular expressions. Maps the strategy line onto one of the 8 names (loosely, by first word), defaulting to Others. Keeps the first line after Response:.
Change it
If a model formats its answer differently and most predictions come back as "Others", fix the matching here. Check the saved raw field in predictions.jsonl to see what the model actually wrote.

gold_nll(model, tok, prompt, ex) → (total_loss, n_tokens)

What
For perplexity. Feeds prompt + Strategy: <gold> + the gold reply, masks everything except the reply (label −100), and returns the summed loss. PPL = exp(total loss / total tokens) over the test set.

main()

Steps
Loads the model (optionally 4-bit), generates greedily in batches, parses, writes each row as it goes, then scores the whole file.
Resumes
It skips IDs already in predictions.jsonl, so a Colab disconnect does not lose work. Delete the file to start over.
Flags
--model any Hugging Face chat model · --load-4bit fits on 8 GB · --limit 200 quick check · --no-ppl skips perplexity (faster).

sage.py

Paper: Section 3 (the method), Appendix B, Tables 1, 2, 4, 6, 8

This is SAGE itself. It is one file with six commands, run in order. Each command saves something the next one loads.

  T1["train-selfret

  C1 --> T2["build-index

  T2 --> C2[("ckpt/index")]
  C1 --> T3["knowledge (optional)
COMET + HEAL"]
  T3 --> C3[("data/knowledge")]
  C1 --> T4["train-fusion
second T5 with
knowledge cross-attention"]
  C2 --> T4
  C3 --> T4
  T4 --> C4[("ckpt/fusion")]
  C1 --> I["infer / eval-retrieval"]
  C2 --> I
  C3 --> I
  C4 --> I
  I --> R["results/sage"]

In plain words, SAGE answers a seeker in five moves, and the code follows them:

  1. Pick likely strategies. The self-retrieval T5 scores all 8 strategies for this context and keeps the top 3 (Eq. 3).
  2. Find candidate replies. For each strategy, look up the 20 training replies with that strategy whose ResID code is closest to the query's (Section 3.2).
  3. Let the model re-generate them. T5 decodes, but may only produce token sequences that spell one of those 20 replies. Beam search keeps the 4 it likes most (Eq. 4).
  4. Re-rank. Score each of the ~12 candidates by strategy probability × "is this a valid reply" × COMET match × HEAL match, and take the best (Eq. 5).
  5. Rewrite. A second T5 reads the context, the chosen strategy and the winning candidate (plus knowledge), and writes the final, new reply (Eq. 6).

Shared helpers and settings

DEV · AMP · SPECIAL · COMET_RELS

What
DEV is "cuda" or "cpu". AMP turns on bf16 mixed precision only on GPUs that support it; the free Colab T4 does not, so it trains in fp32 there (T5 is unstable in fp16). SPECIAL are four marker tokens added to the vocabulary: [STRAT] [RESP] [CAND] [CTX]. COMET_RELS are the four commonsense relations used.

ctx_text(ex, turns=6) → str

What
Turns the last 6 context utterances into one string: "Seeker: ... Supporter: ... Seeker: ...". Every T5 input in the file is built from this.
Change it
The paper does not give a context length. Raising turns gives the model more history (and longer inputs; the tokenizer cuts at 256 tokens). You could also prepend ex["situation"] here.

target_text(strategy, response, use_strategy=True) → str

What
Builds the training target "[STRAT] Question [RESP] How long has this been going on?". This is exactly the sequence in Eq. 1. With the ablation flag it drops the strategy part.

get_tok(path) · batches(xs, n) · load(path) · seed_all(s)

What
Load a tokenizer with the special tokens added; chunk a list; read a JSONL file; fix random seeds.

Stage 1 · The self-retrieval model (train-selfret)

Paper: Eq. 1, Section 3.4 (P_reject), Appendix B

One T5-base model learns two jobs at the same time. This "self" model is reused later for strategy scoring, candidate decoding, judging and embedding, which is why the paper calls it self-retrieval.

selfret_pairs(train, use_strategy, neg_ratio=1.0) → list[(input, target)]

Job A
"context: Seeker: ... " → "[STRAT] s [RESP] r". Learning this teaches the model which strategy fits and what a reply with that strategy looks like.
Job B
"judge: <context> response: <reply>" → "yes" for the real next reply, "no" for a reply taken from a different dialogue. Later, P(yes) becomes σ_valid in Eq. 5.
Assumption
The paper never says how the model learns to reject replies. Random negatives at a 1:1 ratio is our choice.
Change it
Harder negatives (a reply from the same dialogue but the wrong turn, or the right strategy but wrong content) would likely make the judge sharper. Swap the random.choice(train) line.

train_seq2seq(model, tok, pairs, out, epochs, lr, bs, warmup, sched, grad_accum, fp16)

What
A plain PyTorch training loop for any (input text, target text) list: tokenise, compute the loss, AdamW step, learning-rate schedule, gradient clipping. Saves the model after every epoch, so a crash keeps the last epoch.
Note
Padding positions in the labels are set to −100 so they do not count in the loss. Inputs are cut at 256 tokens and targets at 128.

cmd_train_selfret(a)

What
Loads t5-base, adds the special tokens, builds the pairs, trains for 3 epochs at lr 1e-4, batch 16, cosine schedule with 3% warm-up.
Saves
ckpt/selfret/ (a normal Hugging Face model folder).

Stage 2 · ResIDs with an RQ-VAE (build-index)

Paper: Section 3.2, Eq. 2, Appendix B.2.1

The goal is to give every training reply a short code of 4 numbers, for example (17, 403, 88, 251), so that replies with similar meaning share most of their numbers. That code is the ResID. Retrieval then becomes "find replies whose codes differ in the fewest positions" (Hamming distance).

How a code is made, in plain words: turn the reply into a vector. Find the nearest of 512 learned "prototype" vectors and write down its number. Subtract that prototype, which leaves a smaller leftover (the residual). Repeat on the leftover with a second set of 512 prototypes, then a third and a fourth. Each level adds finer detail.

embed(model, tok, texts, bs=64) → Tensor[N, 768]

What
Runs texts through the T5 encoder, averages the token vectors (ignoring padding), and normalises to length 1. Used to embed replies, queries, COMET and HEAL text everywhere in the file.
Change it
This is the single place that decides what "similar" means. Swapping in a sentence-embedding model (for example from sentence-transformers) here would change retrieval, COMET and HEAL scoring at once. Keep the output normalised.

sinkhorn(cost, eps=0.1, iters=10) → code indices

What
During training, plain "pick the nearest prototype" tends to send most replies to a handful of codes. Sinkhorn rebalances the assignment so codes are used more evenly. The paper mentions this ("Sinkhorn regularization mitigates code usage bias").

class RQVAE(d_in=768, d_code=256, levels=4, size=512)

Parts
enc: a small network that shrinks 768 → 256. books: 4 codebooks of 512 vectors each. dec: grows 256 back to 768.
quantise
The residual loop from Eq. 2. Returns the 4 code numbers, the summed prototype vector, and two small losses that pull prototypes and encodings toward each other.
forward
Encode, quantise, decode, and return the loss: reconstruction error + 0.25 × codebook loss + 0.25 × commitment loss. The "straight-through" line lets gradients pass through the non-differentiable "pick nearest" step.
codes
Inference only: vector in, 4 numbers out.
Assumption
The paper mentions a 6-layer Transformer but never says what it reads. We use a small MLP over sentence vectors.

cmd_build_index(a)

Steps
Embed every training reply with the stage-1 encoder → start each codebook from real data points (so no code is dead at the start) → train the RQ-VAE for 50 epochs → compute every reply's code.
Prints
"codes used per level" and "unique ResIDs". If most replies share a few codes, retrieval will be poor; that is the first thing to check.
Saves
ckpt/index/index.pt: the RQ-VAE weights, all codes, and all reply embeddings.

Stage 3 · External knowledge (knowledge, optional)

Paper: Section 3.4 (σ_comet, σ_heal), Section 3.5

SAGE uses two outside sources. COMET is a commonsense model: given "I failed my exam", it guesses the person's intent, need, likely effect and want. HEAL is a knowledge graph of expert mental-health responses. Neither is downloadable from the cloud container, so the Colab notebook runs with --knowledge none. All later code then skips the knowledge terms (Eq. 5 and Eq. 6 shrink to the context-only parts).

cmd_knowledge(a)

What
For each example's last seeker utterance, asks COMET for xIntent/xNeed/xEffect/xWant, and finds the 3 most similar HEAL expert replies by embedding. Caches everything to data/knowledge/{split}.jsonl.
File format
{"id": "test-0-5", "comet": ["xIntent to fix things", ...], "heal": ["It sounds like...", ...]}
Change it
You can plug in any knowledge source by writing files in this format yourself (for example, your own counselling guidelines, or LLM-generated inferences instead of COMET). Nothing else needs to change.

knowledge_map(kdir, split) → {id: row}

What
Loads that cache as a dictionary. Returns an empty one if the folder does not exist, which is how "no knowledge" works.

Stage 4 · The fusion generator (train-fusion)

Paper: Eq. 6, Section 3.5

The retrieved candidate is a real reply from a different conversation, so it may not fit perfectly. A second T5 rewrites it for this conversation, while reading the knowledge.

class FusionT5(t5)

What
Wraps a normal T5 and changes only what the decoder sees. It encodes three texts separately: the context (H_ctx), COMET (H_C) and HEAL (H_H). Two cross-attention layers let the context "look up" relevant parts of COMET and of HEAL. The three are mixed with weights λ₁, λ₂, λ₃ that are learned and forced to sum to 1 (softmax). The decoder then writes the reply from that mixture.
Formula
H_out = λ₁·H_ctx + λ₂·CrossAttn(H_ctx, H_C) + λ₃·CrossAttn(H_ctx, H_H)
Start value
lam = [2, 0, 0] means training starts by trusting the context most (λ₁ ≈ 0.78). The training log prints how λ moves.
Change it
To add a third knowledge source, add another nn.MultiheadAttention, a fourth λ, and a fourth input in fusion_inputs.

fusion_inputs(tok, exs, cands, strategies, kmap, use_comet, use_heal) → (ctx, comet, heal)

What
Builds the three tokenised inputs. The context input is "[STRAT] s [CAND] candidate [CTX] conversation", so the generator knows the strategy and the reply to adapt. Missing knowledge becomes the word "none".

load_index(path) · resid_topk(qcode, qemb, codes, emb, mask, r, use_resid=True)

What
load_index reloads stage 2. resid_topk is the retrieval step: score = −10 × (number of differing code positions) + cosine similarity, so Hamming distance decides and cosine only breaks ties. mask limits the search, for example to replies with a given strategy.
Assumption
The paper only builds ResIDs for replies and never says how the query gets one. We pass the query's context vector through the same RQ-VAE.
Change it
This one function is the retriever. Replace it with FAISS, BM25 or a dense retriever and all of SAGE uses the new one. --no-resid already switches to pure cosine.

cmd_train_fusion(a)

Steps
For each training example, retrieve the best candidate with the gold strategy from a different dialogue (so the model cannot just copy the answer). Then train FusionT5 to turn (strategy, candidate, context, knowledge) into the gold reply.
Saves
ckpt/fusion/fusion.pt, the tokenizer, and which base model was used.

Stage 5 · Inference (infer, eval-retrieval)

Paper: Eqs. 3, 4, 5, Sections 3.3–3.5

strategy_logprobs(model, tok, src) → Tensor[8]

What
The strategy classifier of Eq. 3. Instead of a separate classifier, it asks the self-retrieval model how likely it is to write "[STRAT] s [RESP]" for each of the 8 strategies, and returns those log-probabilities.

class Trie(seqs) · .next(prefix)

What
A prefix tree of token IDs. Given the tokens generated so far, next returns which tokens may come next so the output stays one of the candidate replies.

constrained_beam(model, tok, src, targets, beams) → [(text, score)]

What
Eq. 4. Runs Hugging Face beam search with prefix_allowed_tokens_fn, which sets the probability of every token outside the trie to zero. The result is the candidates the model itself prefers, ranked by its own scores. This is the core "self-retrieval" idea: the generator is the ranker.
Ablation
--no-constraint skips the trie and lets the model generate freely after the strategy prefix.

split_target(t) → (strategy, response)

What
Splits "[STRAT] s [RESP] r" back into its parts.

p_valid(model, tok, ctx, responses) → Tensor[k]

What
σ_valid in Eq. 5. Feeds "judge: ... response: ..." and reads the first output token's probability of "yes" versus "no". This is the job-B training from stage 1 paying off.

class SageModel(a) · .respond(e) · .gold_nll(e, r_star)

__init__
Loads every trained piece once: tokenizer, self-retrieval T5, RQ-VAE index, training replies, knowledge cache and (unless --retrieval-only) the fusion generator.
respond
Produces one reply for one example. Walked through line by line below. Returns {pred_strategy, chosen_strategy, candidate, prediction}.
gold_nll
Loss of the gold reply under the fusion generator, for PPL.
Reuse
This class is the clean entry point if you want SAGE inside your own program. esc_eval.py uses it exactly that way.

cmd_infer(a)

What
Builds a SageModel, calls respond on every test example, writes predictions.jsonl, then scores it with metrics.evaluate_file plus PPL. Saves metrics.json including every setting used.

cmd_eval_retrieval(a)

What
Tables 4 and 8. For each test example, makes a pool of 100 test replies that includes the gold one, shortlists 20 by ResID, ranks them with constrained beam search, and checks where the gold reply lands.
Assumption
The paper never says how large its pool is. Pool size changes the numbers a lot; on the full 3.5k-reply test pool BM25 gets R@10 11.4. Use --pool-size to test this.

One reply, step by step: inside respond()

Follow the code from line 538 of sage.py with the example row above.

  1. Build the input. src = "context: Seeker: hi Seeker: i'm nereida Supporter: Hi, do have any issues... Seeker: i am in disputed mod with my friends"
  2. Get the query's ResID. embed gives a 768-number vector q; rq.codes turns it into 4 code numbers qcode.
  3. Score strategies. strategy_logprobs → softmax with temperature τ (--tau) → keep the top --bs-strat = 3, say Question, Reflection of feelings, Restatement.
  4. Retrieve per strategy. For each of the 3, resid_topk picks 20 training replies that carry that strategy and have the nearest ResID.
  5. Constrained decoding. constrained_beam lets the T5 choose among those 20, keeping 4 beams (--br). Now there are up to 3 × 4 = 12 candidates, each tagged with its strategy probability.
  6. Fallback. If nothing came back, use a single Information reply (Section 3.3).
  7. Re-rank (Eq. 5, in log space). score = log σ_strat + log P(yes)/δ + α·log(mean COMET similarity) + β·log(max HEAL similarity). The last two are skipped when there is no knowledge.
  8. Choose. The highest score gives s_star (strategy) and r_star (candidate reply).
  9. Rewrite (Eq. 6). FusionT5 generates the final reply with beam 4, repetition penalty 1.2, no repeated 3-grams, at least 10 tokens. With --retrieval-only, r_star itself is the answer.
Which strategy counts for ACC? pred_strategy is the top-1 strategy from step 3, not the one that won re-ranking (chosen_strategy). That matches how the paper describes the strategy classifier. If you want to report the re-ranked one instead, change the return line of respond.

esc_eval.py

Paper: Section 4.1, Table 5, Table C.15 (the second dataset, ESC-Eval)

ESConv tests one reply at a time against a gold reply. ESC-Eval tests a whole conversation instead. A "seeker" model reads a role card (a short description of a person and their problem) and chats with your system for 5 turns. A judge model then scores the conversation from 0 to 4 on seven qualities. The paper's own Table 5 used three of its authors as raters, which cannot be repeated, so this script uses ESC-Eval's official automatic judge.

class Chat(model_id, load_4bit, max_new_tokens, adapters, trust_remote_code)

What
A small wrapper: give it a list of chat messages, get back the model's reply (greedy). adapters loads one LoRA per scoring dimension for the ESC-RANK judge, and use(name) switches between them.

_alternate(messages)

What
Merges back-to-back messages from the same role. Some chat templates (Mistral's) crash otherwise.

make_system(spec, args) → reply(history)

What
Returns a function that answers a conversation. "sage" wraps SageModel.respond. "llm:<model>" wraps a chat LLM with the llm_baseline prompt.
Change it
To evaluate your own system on ESC-Eval, add a branch here that returns any function taking [("usr", text), ("sys", text), ...] and returning a string.

roleplay(args)

What
For each role card: the system opens with ESC-Eval's greeting, then seeker and system alternate for --turns rounds. Saves after every card to dialogs.json, and skips finished cards on restart.

load_judge(args) · score(args) · summarise(scores)

What
Loads ESC-RANK (InternLM2-chat-7B + 7 LoRAs) or any chat LLM as judge. For each dialogue and each of the 7 dimensions, sends ESC-Eval's scoring prompt and reads the first digit 0–4. summarise averages them and also reports a +1 shifted 1–5 version to sit beside the paper's 5-point scale.
Note
The odd spellings in DIMENSIONS ("fluecy", "suggection") are deliberate. They match the prompts ESC-RANK was trained on.

compare.py

Has the paper's reported numbers typed in (PAPER for Tables 1, 2, 4 and ESC_PAPER for Table 5). It scans every results/*/metrics.json and retrieval.json, guesses which paper row each run matches from the folder name (a folder containing "qwen" is matched to Qwen-2.5-7B), and prints a Markdown table with our row above the paper's row.

Naming matters. Put the model name in the output folder (--out results/qwen, results/sage) so compare.py can pair it. Folders starting with sage_ are ablations and are printed without a paper row.

The notebooks

SAGE_colab.ipynb contains no method code. It mounts Google Drive, installs packages, and calls the scripts above with !python ...: a 200-example quick check, the full LLM baselines, the full SAGE pipeline with --knowledge none, three ablations, compare.py, and a zip of the results.

SAGE_reproduction.ipynb is the opposite: it pastes the code of every script into its own cells (sections 1–8) so it runs without the .py files. Its QUICK = True switch at the top uses 200 test examples and 1 epoch.

Two copies of the code. If you change sage.py, the self-contained notebook still has the old version, and the other way round. Pick one to work in. For your own project, the .py files plus SAGE_colab.ipynb are easier to keep in sync.

How to modify it

Common changes, where to make them, and what else must change with them.

Use a bigger or smaller backbone

Pass --base google/flan-t5-large (or t5-small for fast tests) to both train-selfret and train-fusion. Everything else adapts: the RQ-VAE reads the vector size from the data, and FusionT5 reads d_model from the model config. Any T5-family model works.

Use a decoder-only LLM (Qwen, LLaMA) instead of T5

This is a larger change, because sage.py assumes an encoder-decoder model in four places: embed (uses model.encoder), constrained_beam and p_valid (use decoder_start_token_id), and FusionT5 (replaces the encoder output). You would switch to AutoModelForCausalLM, put the input and target in one sequence (as llm_baseline.gold_nll does), take embeddings from the last hidden layer, and redesign fusion (for example, put COMET and HEAL text into the prompt instead of cross-attention).

Change the retriever

Replace resid_topk. It must return a list of indices into the training rows, best first, respecting mask. Try --no-resid first to see how much ResIDs help compared with plain cosine.

Change how candidates are re-ranked

Weights: --tau, --delta, --alpha, --beta; tune on --eval-split valid, never on test. New terms: add to log_s inside respond, for example a safety classifier's log-probability or an emotion-match score.

Add your own knowledge

Write data/knowledge/{train,valid,test}.jsonl with {"id", "comet": [...], "heal": [...]} rows from any source, then run train-fusion and infer with --knowledge data/knowledge.

Use a different dataset

Write a converter that outputs the data row shape into data/<name>/{train,valid,test}.jsonl and use --split <name>. If the labels differ, edit STRATEGIES. The fields every script really needs are id, dialog_idx, context, query, response, strategy and num_prev_turns.

Speed things up while experimenting

--limit 200 on infer, eval-retrieval and llm_baseline; --epochs 1 on training; --base t5-small; --br 2 --r 10 at inference.

Using SAGE in your own code

After the training commands have run, you can call SAGE from any Python file. This is the same pattern esc_eval.py uses.

from types import SimpleNamespace
from sage import SageModel

args = SimpleNamespace(
    split="paper", selfret="ckpt/selfret", index="ckpt/index", fusion="ckpt/fusion",
    knowledge="none", eval_split="test",
    bs_strat=3, r=20, br=4, tau=1.0, delta=1.0, alpha=0.5, beta=0.5,
    no_constraint=False, no_resid=False, no_comet=False, no_heal=False, retrieval_only=False,
)
sage = SageModel(args)          # loads all models once

example = {
    "id": None,
    "context": [
        {"speaker": "usr", "text": "I failed my driving test again and I feel useless."},
    ],
    "query": "I failed my driving test again and I feel useless.",
}
out = sage.respond(example)
print(out["chosen_strategy"], "|", out["prediction"])

split still matters here: it says which training replies form the retrieval pool, so it must match the split you trained the index on.

Glossary

Seq2seq / T5
A model with an encoder that reads the input and a decoder that writes the output. T5-base has about 220M parameters.
Teacher forcing
Feeding the gold answer to the decoder to measure how likely the model finds it. Used for training loss and perplexity.
Beam search
Generating while keeping the k best partial outputs at every step, instead of only the single best.
Constrained decoding
Beam search where some tokens are forbidden at each step. Here, only tokens that keep the output on a candidate reply are allowed.
Trie
A tree where shared beginnings of sequences are stored once. Lets you ask "what may come next?" quickly.
Embedding
A list of numbers that represents a text, so similar texts get similar numbers.
Cosine similarity
How closely two embeddings point in the same direction, from −1 to 1.
RQ-VAE
Residual-quantised variational autoencoder. Compresses a vector into a few code numbers, each level coding what the previous ones missed.
Codebook
The set of 512 learned prototype vectors at one RQ-VAE level.
ResID
The paper's name for a reply's 4-number RQ-VAE code.
Hamming distance
How many positions differ between two codes. (17, 403, 88, 251) vs (17, 403, 90, 12) is 2.
Sinkhorn
An iterative method that balances an assignment so every code gets used.
Straight-through estimator
A trick that copies gradients across a step that has no gradient (like "pick nearest").
Cross-attention
One sequence (the context) reads from another (the knowledge), pulling in the parts most relevant to each of its tokens.
Perplexity (PPL)
exp(average loss per token). Roughly, how many words the model was "choosing between". Lower is better.
LoRA
A small add-on weight set that adapts a big model to a task. ESC-RANK has one per scoring dimension.
4-bit loading
Stores weights in 4 bits instead of 16 so a 7B model fits on an 8 GB GPU, at a small quality cost.
Ablation
Removing one component and re-measuring, to see how much that component contributed.
